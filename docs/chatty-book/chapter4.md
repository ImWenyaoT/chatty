# 第 4 章：五个 Tool

Tool 是 Model 观察外部世界的方式。Chatty 一共有五个 Tool，每个 Tool 只回答一个明确的问题。

| Tool                     | 要回答的问题             | 返回给 Model 的内容  |
| ------------------------ | ------------------------ | -------------------- |
| `get_user_profile`       | 这个用户有什么历史偏好？ | 合并本轮约束后的画像 |
| `search_products`        | 哪些商品符合类目和价格？ | 候选商品             |
| `check_inventory`        | 候选商品现在是否有货？   | 库存状态             |
| `retrieve_knowledge`     | 推荐这些商品有什么依据？ | 知识原文块           |
| `get_marketing_strategy` | 应该用什么语气表达？     | 语气、要求和禁用词   |

商品搜索、库存检查和知识检索看起来都像“搜索”，但它们查询的是不同事实。

商品搜索从用户需求得到候选集合；库存检查确认候选是否可售；知识检索寻找能够支撑推荐理由的内容。商品目录变化、库存变化和知识文档变化的原因不同，把它们拆开后，每个 Tool 的输入和结果都更容易验证。

前三个 Tool 存在依赖顺序：

```text
get_user_profile → search_products → check_inventory
```

没有画像就无法确定完整搜索条件；没有候选商品也不知道应该检查哪些库存。知识检索和营销策略分别依赖商品与画像，但彼此不依赖，因此可以交换次序。

Model 提出的参数并不会直接成为业务事实。Harness 会用用户本轮明确的类目和预算收窄搜索条件。当前输入适配器没有提取标签，所以 Model 也不能凭空增加标签作为硬筛选条件。

如果商品搜索返回空数组，库存 Tool 仍会接收空数组。这一步看似没有查询内容，却形成了明确证据：当前条件下没有候选商品可以继续检查。完成其余 Tool 后，Agent 才能向用户提出放宽预算的澄清问题。

Model 可以在修改条件后重新调用 Tool，但 Harness 会记录参数。如果同一个 Tool 使用完全
相同的参数调用到第 4 次，Harness 会终止这次重复调用，防止 Agent 在没有取得新信息时
一直循环。
